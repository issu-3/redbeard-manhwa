
## 2025-05-18 - Zustand Selector Pattern for High-Volume List Items
**Learning:** Using `const store = useAppLibraryStore()` without a selector in a heavily used component like `SeriesCard` subscribes that component to *every* global state change in the store. When rendering lists or grids (e.g. `Carousel`, `SearchClient`), this creates an O(N) re-render bottleneck across the entire app whenever completely unrelated library state changes.
**Action:** Always use specific state selectors (`useAppLibraryStore(state => state.specificData)`) combined with `React.memo` when a component represents a list item connected to a global store to prevent cascading O(N) re-renders.
## 2025-05-18 - Zustand Full Store Subscription Anti-Pattern
**Learning:** Destructuring a Zustand store (e.g., `const { property } = useStore()`) implicitly subscribes the component to ALL state changes within that store. In complex views with many list items (like `BookmarkButton` rendered in grid views), this causes massive O(N) unnecessary re-renders when entirely unrelated store data changes.
**Action:** Always use explicit atomic state selectors (e.g., `const property = useStore((state) => state.property)`) to strictly limit component subscriptions to the specific state they consume. Furthermore, for store actions consumed in event handlers, use `const storeState = useStore.getState()` inside the handler to avoid subscribing to actions entirely.
