## 2024-05-18 - [Missing Auth Checks on Admin Endpoints]
**Vulnerability:** Several API routes under `/api/admin` (e.g. `drive/scan` and `resolver-status`) lacked authentication checks and were publicly accessible.
**Learning:** Next.js route handlers in this application do not enforce global authentication or role authorization via middleware. Each protected route, including those logically grouped under an `admin` folder, must manually verify user session and roles using `await auth()`.
**Prevention:** Always manually include role-based authentication checks (using `await auth()`) for any sensitive route handlers in Next.js applications that lack a global middleware auth layer.
## 2024-05-18 - [Unauthenticated Cron Execution Bypass]
**Vulnerability:** The cron job API routes for database backups (`/api/cron/backup`) and recovery tests (`/api/cron/recovery-test`) could be triggered unauthenticated by appending `?force=true` to the URL.
**Learning:** Using overly permissive boolean checks (`!isDev && !isValidCron && !request.nextUrl.searchParams.has('force')`) allows attackers to bypass required authentication mechanisms. In this case, `!has('force')` evaluates to `false` when `?force=true` is present, causing the entire unauthenticated error check to be skipped, triggering expensive background tasks and leading to resource exhaustion (DoS) and potential external API quota issues.
**Prevention:** Avoid relying on query parameters like `force` to bypass authentication checks on expensive operations. Always ensure that unauthenticated users cannot bypass security checks via predictable parameters.
